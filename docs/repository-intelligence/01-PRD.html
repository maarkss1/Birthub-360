📋 Visão Geral do Produto

Nome do Produto

Birth Hub 360 — Central de Inteligência Comercial

Descrição

Plataforma CRM de inteligência comercial com IA para equipes de alta performance, combinando gestão de relacionamento com clientes, prospecção inteligente, análise de dados comerciais e automação de processos de vendas.

Problema que Resolve

Centraliza e automatiza o ciclo comercial completo — desde a prospecção de leads até o fechamento de negócios — com inteligência artificial aplicada a cada etapa, eliminando processos manuais e fornecendo insights em tempo real para tomada de decisão.

Objetivo

Aumentar a produtividade e eficácia de equipes comerciais através de uma plataforma unificada que combina CRM, inteligência de mercado, automação e IA assistiva.

Proposta de Valor

  • CRM 360º com visão completa de leads, empresas e contatos
  • Prospecção inteligente com enriquecimento automático de dados
  • Inteligência comercial com análises e previsões
  • Automação de cadências e follow-ups
  • IA assistiva para geração de conteúdo e coaching
  • Integrações nativas com ferramentas comerciais

👥 Público-Alvo e Personas

Público-Alvo

Equipes comerciais de empresas B2B, incluindo SDRs, Closers, Gestores e Diretores comerciais.

Personas

Persona Papel Objetivos Dores
SDR Estrategista SDR Qualificar leads rapidamente, aumentar taxa de conversão Falta de contexto sobre empresas, manualidade no processo
Closer Executivo CLOSER Fechar negócios, gerenciar pipeline Perda de visibilidade do funil, follow-ups manuais
Gestor Comercial GESTOR Supervisionar equipe, analisar métricas Falta de dados em tempo real, dificuldade de previsão
Diretor de Vendas ADMIN Estratégia comercial, análise de performance Dados fragmentados, falta de visibilidade executiva

Jobs To Be Done

  • Encontrar e qualificar novos prospects
  • Gerenciar pipeline de oportunidades
  • Executar follow-ups e cadências
  • Analisar performance comercial
  • Automatizar tarefas repetitivas
  • Obter insights de mercado e concorrência

📐 Regras de Negócio

Controle de Acesso (RBAC)

Papel Nível Permissões
ADMIN 100 Acesso total, gestão de usuários, configurações
GESTOR 75 Visibilidade executiva, gestão de equipe
CLOSER 50 Gestão de pipeline, fechamento de negócios
SDR 40 Prospecção, qualificação de leads
VISUALIZADOR 10 Apenas leitura
src/lib/auth/authorization.ts

Multi-tenancy

Todos os dados são isolados por organização (tenant) através de RLS (Row Level Security) no PostgreSQL e middleware requireTenant no backend.

src/shared/middlewares/authorization.ts

Status de Lead

  • Lead Recebido → Cadência Iniciada → Qualificação (SDR)
  • Reunião Agendada → Convertido em Oportunidade
  • Proposta Enviada → Call/Visita Agendada
  • Negócios Perdidos / Negócios Ganhos
prisma/schema.prisma (LeadStatus enum)

Regras de Enriquecimento

  • Enriquecimento automático via BrasilAPI (CNPJ, CEP)
  • Integração opcional com Apollo para dados firmográficos
  • Look-alike scoring via pgvector
  • Cache TTL configurável (default: 86400s)

📋 Requisitos

Requisitos Funcionais

  • Autenticação via e-mail/senha e OAuth (Google)
  • Gestão de usuários com papéis hierárquicos
  • CRUD completo de leads, empresas e contatos
  • Pipeline visual Kanban com drag-and-drop
  • Busca e filtros avançados
  • Enriquecimento automático de dados
  • Geração de conteúdo via IA
  • Automação de cadências e follow-ups
  • Integrações bidirecionais com CRMs externos
  • Analytics e relatórios exportáveis

Requisitos Não-Funcionais

Categoria Requisito Evidência
Performance Tempo de resposta < 2s para operações CRUD package.json (Vite, React 19)
Segurança Autenticação, autorização, RLS multi-tenant src/lib/auth/, prisma/schema.prisma
Escalabilidade Workers separados para processamento assíncrono worker.ts, BullMQ
Observabilidade OpenTelemetry, Sentry, Prometheus src/lib/telemetry/, src/lib/monitoring/
Disponibilidade Health checks e graceful shutdown src/bootstrap/healthchecks.ts
Compatibilidade Mobile via Capacitor (Android/iOS) capacitor.config.ts, android/, ios/

Limitações Atuais

  • Dependência de PostgreSQL remoto (sem Postgres local no compose principal)
  • Alguns módulos (Voice Hub, Cadence) parcialmente implementados
  • Dependência de múltiplas chaves de API externas
  • Infraestrutura Kubernetes configurada mas não ativa

Riscos

  • Complexidade de sincronização bidirecional com Bitrix24
  • Gerenciamento de credenciais de múltiplas integrações
  • Performance com grandes volumes de dados
  • Consistência de dados entre sistemas externos

Dívida de Produto

  • Módulos executivos aposentados (treinamento, proposta comercial)
  • Dependência de infraestrutura externa (Postgres remoto)
  • Alguns workflows de automação incompletos
  • Documentação de alguns módulos desatualizada
