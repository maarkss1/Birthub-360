🔐 Fluxo de Autenticação

Login Flow

1. Acesso à Tela de Login

Usuário acessa /login → LoginScreen component

src/features/auth/components/LoginScreen.tsx

2. Escolha do Método de Login

Opções: E-mail/senha ou Google OAuth (se configurado)

3. Submissão de Credenciais

POST para /api/auth/sign-in/email ou OAuth callback

src/lib/auth.ts (Better Auth)

4. Sucesso de Autenticação

Cookie de sessão definido → Redirecionamento para /app

5. Primeiro Acesso

Se senha temporária → ChangePasswordGate → WelcomeScreen

Cadastro Flow

1. Acesso à Tela de Cadastro

Usuário acessa /welcome → WelcomeScreen com formulário de cadastro

2. Preenchimento de Dados

Nome, e-mail, senha (validação Zod)

3. Criação de Conta

POST para /api/auth/sign-up/email → Criação de User + Organization

4. Verificação de E-mail

Envio de e-mail de verificação (se SMTP configurado)

5. Login Automático

Após verificação → Redirecionamento para /app

🛡️ Guards e Proteção de Rotas

Componentes de Guard

Guard Propósito Lógica
ProtectedRoute Verifica autenticação Redireciona para /login se não autenticado
RequireRole Verifica papel (RBAC) Verifica hierarquia de papéis via authorization.ts
RequireModuleAccess Verifica acesso a módulo executivo Consulta ModuleAccessGrant no banco

Proteção no Backend

  • authenticateToken: Middleware que valida sessão Better Auth
  • requireTenant: Middleware que resolve organizationId da sessão
  • requireRole: Middleware que verifica papel via authorization.ts
  • Rate Limiting: Limites por IP, organização e rota específica
src/components/layout/ProtectedRoute.tsx, src/components/layout/RequireRole.tsx, src/shared/middlewares/

Proteção Defesa em Profundidade

Rotas sensíveis (Commercial Intelligence, Mesa de Tratamento, Copiloto IA) têm proteção dupla: guard no frontend E middleware no backend. Isso previne acesso via URL direto.

src/App.tsx (exemplos de RequireRole), src/bootstrap/routes.ts
