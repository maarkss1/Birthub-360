1. Architecture Overview

The AtlasGR architecture strictly follows Clean Architecture separation principles (Presentation, Application, Domain, Infrastructure, Shared, Core, Config, Tests).

USER (Browser / Client)
  ↓
[ Presentation Layer ] (React / Vite Frontend)
  ↓
[ Routing / Express ] (server.ts)
  ↓
[ Controllers ] (Orchestrators, No Business Logic)
  ↓
[ Application Layer ] (Use Cases)
  ↓
[ Domain Layer ] (Interfaces, Entities, Framework-independent)
  ↓
[ Infrastructure Layer ] (Prisma Repositories, Adapters, AI Gateways)
  ↓
[ Databases & External Services ] (PostgreSQL, Redis, Meilisearch, LiteLLM)

3. Security & Compliance

  • Row Level Security (RLS): Enforced at the database level for tenant isolation via Prisma static migration DDL.
  • Authentication Bypass: ALLOW_DEV_AUTH_BYPASS=true is available for local dev but blocked in production.
  • Log Redaction: Pino logger explicitly redacts sensitive fields (passwords, auth headers).
  • Dependency Injection: Implemented via a centralized manual container (src/shared/di/container.ts). Singletons are prohibited.
  • Production URL Validation: PUBLIC_BASE_URL cannot be localhost in production mode.
